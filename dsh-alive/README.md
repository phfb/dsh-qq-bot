# dsh-alive

她心里挂着没落地的事到期了，由她自己主动开口一次。

不是定时器随机发消息 —— **随机只会让人烦，心里挂着事才会让人觉得有人在那儿。**

```
你说「我去拿个外卖」
        ↓  关键词快筛 → 建一个 open loop（18 分钟，已抖动）
18 分钟后你还没回来
        ↓  过 12 道闸门 + 打分 ≥ 55
插件投一条"她自己的念头"进 QQ 会话
        ↓
agent 带人格 + 记忆现场说一句  →  dsh-qq-bot 转发到你手机
```

---

## 依赖

必须和 **dsh-qq-bot** 一起用。它不自己连 QQ：投递目标是 `qq-<你的QQ号>` 这个会话，
`assistant/message` 出去之后由 dsh-qq-bot 负责发到 QQ。

## 装法

> 下面是示例路径，换成你自己的实际目录。
> **推荐做法**：让 `node_modules\dsh-alive` 直接 junction 到源码目录，这样改源码就等于改在跑的插件，不用来回拷一份。
> 第 3 步手写的 YAML 也可以完全跳过 —— 装好之后双击 `tools\settings-alive.cmd`，在窗口里点一遍就行，见下面「工具：图形化设置」。

1. 建 junction（**不做这一步 Loader 找不到包**，dsh-qq-bot 踩过）：

   ```powershell
   New-Item -ItemType Junction `
     -Path   "<你的 profile 目录>\node_modules\dsh-alive" `
     -Target "<本目录的绝对路径>"
   ```

   > ⚠️ 别用 `Copy-Item` 往 `plugins\` 里拷一份再把 junction 指过去 —— 那样会变成两份代码，改了 release 里的、跑的还是旧那份。这套插件就踩过：设置窗口写进去的 `alive-config.json` 一直没人读，因为 junction 指的那份是旧代码（没有配置热载）。

2. `cordis.patch.yml` 末尾追加：

   ```yaml
   - insert:
       - id: dsh-alive
         name: dsh-alive
         config:
           enabled: true
           dryRun: false
           targetSession: 'auto'
           selfUin: '<你的 QQ 号>'
           dataDir: '<数据目录，必须和 dsh-qq-bot 用同一个>'
           minSilenceMin: 12
           cooldownMin: 60
           maxPerHour: 1
           maxPerDay: 2
           threshold: 55
   ```

3. 重启 DSH。（`cordis.patch.yml` 改了不会自己热载，宿主只在启动/显式重载插件时读它。）

4. 装好之后：双击 `tools\settings-alive.cmd` 改参数，保存即热应用 —— 不用再动 YAML。

5. **涩涩（对话驱动的那一维）默认是关的，而且面板里一开始看不见。**
   想开的话看下面 [§涩涩：两层开关](#涩涩两层开关) —— 那里写了面板上哪一行、代码里哪一行，
   也写了为什么建议搭配 purge-plus 插件一起用。

## 配置项

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 总开关 |
| `dryRun` | **true** | true = 只算不投，日志里能看到"她本来会说什么" |
| `targetSession` | `auto` | 投到哪个会话。`auto` = 跟着 dsh-qq-bot 的会话映射走（推荐，换号也不用改）；也可以写死 `qq-<你的QQ号>` |
| `selfUin` | `（空）` | 你本人的 QQ 号，兜底用来找会话（建议填上） |
| `minSilenceMin` | 12 | 你刚说完话的静默期 |
| `cooldownMin` | 45 | 两次主动的基础间隔（被忽略翻倍，封顶 6h） |
| `maxPerHour` / `maxPerDay` | 1 / 4 | 配额 |
| `threshold` | 55 | 打分阈值，越高越沉默 |
| `maxAttempts` | 2 | 每条事最多追几次（按类型还会再收） |
| `quietHours` | `[]` | 完全禁言时段，如 `['03:00-06:00']` |
| `deepNightHours` | `['03:00-06:00']` | 这个时段只放"睡了"型 |
| `staleMin` | 30 | 念头超过这么久没投就作废 |
| `includeRecall` | false | 是否调 ebbinghaus 召回旧事塞进念头 |
| `moodFillHours` | 6 | 情绪速率的基准：1.0x 倍率下从 0 攒到 100% 要几小时（设置窗口「情绪速率」组里可改） |
| `moodRates` | 全 1.0 | 七个情绪维度各自的速率倍率（0.1x ~ 10x）。详见下面「情绪值」一节 |
| `moodSnapshotIntervalMin` | 5 | 情绪快照 `alive-mood.json` 最短多久写一次（分钟，1~1440）。详情见「存哪儿」 |
| `lustModeEnabled` | **false** | 涩涩那颗**真开关**。只有源码里 `LUST_ENABLED = true` 之后面板才会露出这一行 |
| `lustFloorPercent` | 20 | 涩涩余温下限（%）：事后回落到这儿就停住 |
| `lustSelfCapPercent` | 70 | 涩涩自涨封顶（%）：靠自己爬最多到这儿，再往上只能靠对话 |
| `lustDecayHours` | 4 | 涩涩回落到余温下限要多久（小时）—— 「回复 / 回满」那份基准时间就是它 |
| `lustFillHours` | 6 | 涩涩自涨基准（小时）：从余温下限爬到自涨封顶用多久 |
| `lustTeaseStepPercent` | 25 | 涩涩单次涨幅（%）：你挑逗一次顶上去多少 |
| `tickMs` | 60000 | 心跳间隔（毫秒）。**改了要重启 DSH**（定时器不会重建） |
| `dataDir` | `~/.dsh-qq-bot` | 状态 / 日志 / 配置都落这儿，和 dsh-qq-bot 用同一个。**改了要重启 DSH** |

## 工具：图形化设置（`tools\settings-alive.ps1`）

不想为了改个数字去动 `cordis.patch.yml` 就用它 —— 双击 **`tools\settings-alive.cmd`**，弹一个独立窗口（和 dsh-qq-bot 的 `settings-ui.ps1` 同一套做法，WinForms，深色皮）。

> 前提：跑的是**带配置热载的版本**（`lib/index.js` 里有 `watchFile(alive-config.json)`）。旧版没有这段，窗口存进去的文件没人读 —— 表现就是「保存成功，但一点变化都没有」。装的时候照上面「装法」把 junction 直接指到本目录，别另拷一份。

六组：

| 分组 | 字段 |
|---|---|
| 情绪速率 | `moodFillHours` + 八颗滑条（想他 / 吃醋 / 暖意·涨 / 暖意·掉 / 担心 / 闲得慌 / 恼火·消气 / 涩涩） |
| 涩涩（对话驱动） | **只有源码里 `LUST_ENABLED = true` 才会出现**：`lustModeEnabled` 开关 + 余温下限 / 自涨封顶 / 回落耗时 / 自涨基准 / 单次涨幅 |
| 开关与目标 | `enabled` / `dryRun` / `targetSession` / `selfUin` |
| 节奏 | `minSilenceMin` / `cooldownMin` / `maxPerHour` / `maxPerDay` / `threshold` / `maxAttempts` |
| 时段 | `quietHours` / `deepNightHours`（多个用逗号分隔，格式 `03:00-06:00`） |
| 其他 | `includeRecall` / `moodSnapshotIntervalMin` / `tickMs` / `staleMin` / `dataDir` |

### 它改的是哪份文件

**`<dataDir>\alive-config.json`**。窗口顶部会把完整路径打出来。

- 点「保存」→ 写进 `alive-config.json`（UTF-8 **无 BOM**）→ 插件 `watchFile` 到变化**立刻热应用**，不用重启 DSH；日志里会多一行 `配置文件变了，已热应用`。
- 这份配置**优先于** `cordis.patch.yml` 里的出厂值（按 `{...YAML, ...alive-config.json}` 合并）。
- 插件首次启动时，如果还没有 `alive-config.json`，会按当时真正生效的那套值落一份基线 —— 所以窗口一打开看到的就是你正在跑的配置，不是一堆空控件。
- 界面上没露出来的字段，保存时原样保留。

**两个例外，改了要重启 DSH 才生效**（都是插件启动时就定死的东西）：

| 字段 | 为什么 |
|---|---|
| `tickMs` | 心跳用的是 `setInterval(config.tickMs)`，定时器已经建好，改数字不会重建 |
| `dataDir` | `alive-config.json` / `alive-state.json` / `logs\` 的路径在插件启动时就算出来了 |

其余字段（开关、节奏、时段、阈值）都是每轮心跳现读，存完下一分钟就按新值走。

### `dataDir` 怎么定

**插件侧**（插件往哪写）先看 `cordis.patch.yml` 里的 `dataDir` —— 这是唯一能打破「先有鸡还是先有蛋」的入口：插件得先知道目录，才能去那儿读 `alive-config.json`。YAML 里没写就用代码默认值 `~/.dsh-qq-bot`。

**窗口侧**（设置窗口读哪份）先看 `tools\bot-config.json` 的 `dataDir`，没有就退回 `~/.dsh-qq-bot`。

两边必须指同一个目录，否则就是那个经典症状：保存了，插件没反应。`alive-config.json` 里那个 `dataDir` 只是把当前值记下来，改它要重启 DSH 才生效。

换机器的做法：

```powershell
cd <本目录>\tools
Copy-Item bot-config.example.json bot-config.json
```

改掉里面的 `dataDir` / SnowLuma 路径 / DSH 路径，然后重启 DSH 让插件读到新目录。窗口里「其他」那一组的 `dataDir` 别随手改 —— 它同时也是窗口下次找配置的依据，在这儿改容易两边错位。

### 「看运行状态」

右边那个按钮用记事本直接打开 **`alive-state.json`**，能看到今天已经投了几次、静音到什么时候、现在挂着哪几个 open loop、各条被追了几次。窗口顶部的说明区也会先显示一遍摘要（`enabled` / 静音到点 / 今日已投）。

这个文件是运行状态，**不是配置** —— 别在那儿改，改了下一轮心跳会被插件覆写。

### 它管不到的

你在 QQ 里说「别吵」触发的硬静音、`我在开会` 触发的软静音，都是**运行时状态**，落在 `alive-state.json` 里，窗口不碰。要解就按上面那张表说「我忙完了」。

## 情绪值（七维）

`lib/mood.mjs` 管着七个数，界面上一律按**百分比**显示（恼火底层是 0~60 的欠账刻度，同样换算成百分比）：

| 维度 | 什么时候涨 | 什么时候掉 |
|---|---|---|
| 想他 `missing` | 他不在，深夜更快 | 他回来 |
| 吃醋 `jealousy` | 他半小时没在 QQ 冒头 | 他出现 |
| 暖意 `warmth` | 被哄（"乖""想你""抱抱"这类） | 自己冷掉 |
| 担心 `worry` | 凌晨他还没消息 | 白天回落 |
| 闲得慌 `boredom` | 越闲越涨，想他越久涨得越快 | 他回来 |
| 恼火 `annoyanceDebt` | 被忽略 / 被赶走 | 自己消气 |
| 涩涩 `lust` | **不是攒的**：你在 QQ 里挑逗她 → 顶上去一截 | 事后往余温下限回落；之后随「想他」自己爬，封顶 70% |

### 速度和满值时间

每颗滑条是**速率倍率**，0.1x ~ 10x，乘在速度上：

```
满值时间 = moodFillHours ÷ 倍率          （moodFillHours 默认 6）

0.1x → 60.0 小时     0.5x → 12.0 小时     1.0x → 6.0 小时
3.0x → 2.0 小时      10x  → 0.6 小时（36 分钟）
```

窗口里每颗滑条右边都会把算好的时间当场写出来，拖滑条实时变。最上面那个数字框（默认 6.0 小时）是全局基准，除涩涩之外的滑条都拿它当 1.0x（涩涩那一维的基准在它自己那组里，见下一节）。

几条不是"攒出来"的，单独说明：

| 滑条 | 意思 |
|---|---|
| 暖意·涨 | 被哄一次涨多少（基准 +30%，倍率乘上去）。事件型，没有满值时间 |
| 暖意·掉 | 满值多久冷光（默认 6 小时） |
| 恼火·消气 | 60 点欠账多久消完（默认 6 小时） |
| 涩涩 | **默认那行是灰的**（锁在 1.0x），而且它的时间根本不按"攒满"算 —— 见下一节 |

### 涩涩：两层开关

**这是唯一一维不是"随时间攒"的情绪。** 它一整条链路是这样：

```
你在 QQ 里挑逗她  →  顶上去一截（默认 +25%）
        ↓
顶上去之后她说话更主动（参与打分，最多 +12 分；主情绪是它时语气提示变 flirty）
        ↓
事后慢慢往回落，落到「余温下限」（默认 20%）就停住 —— 回落耗时默认 4 小时
        ↓
落到底之后靠自己随「想他」慢慢爬（想他越重爬得越快）
爬到「自涨封顶」（默认 70%）就不动了 —— 70% 以上只能靠你再挑逗
```

**三道门，一档一档往上开：**

| 状态 | 怎么到 | 面板上什么样 |
|---|---|---|

| ① 整组不存在 | `LUST_ENABLED`（`lib/mood.mjs` 顶上）保持 `false` | 设置窗口里根本没有「涩涩」这一组 |
| ② 显示但滑条锁着 | `LUST_ENABLED = true`，面板上那颗正式开关**没勾** | 这一组露出来了，涩涩那行倍率滑条灰着、不可拖（按 1.0x 显示） |
| ③ 可调且生效 | 再勾上组里第一行 `lustModeEnabled`（存 `alive-config.json`） | 滑条能拖了，拖完**立刻参与演化** |

> 2026-10-26 改过一次：以前 `LUST_SLIDER_ENABLED` 是个「滑条锁」，设成 `false` 就等于
> 倍率永远钉死 1.0x —— 面板上那颗正式开关勾了也照样拖不动，这一维只能按基准速度走。
> 现在它只管「这颗控件在不在」，**能不能拖交给正式开关**，勾上就真的算数。

**怎么打开（两步，缺一步都不算开）：**

```js
// ① lib/mood.mjs 顶上那一行改成 true，然后重启 DSH —— 面板里才会出现「涩涩」那组
export const LUST_ENABLED = true
```

② 双击 `tools\settings-alive.cmd` → 「涩涩（对话驱动）」组 → 勾上「启用涩涩模式（真正打开的那颗）」→ 保存。

到这里就全开了：那一维会开始随对话动，**涩涩自己的那颗速率滑条也能拖了**（拖完立刻生效）。
（保存即热应用，不用再重启；只有第 ① 步那一行要重启。）

> **建议搭配 purge-plus 插件使用。**
>
> 涩涩这一组和上面那条**百分比条子的锁**是**隔离开**的，互不牵连：
> 条子（速率滑条）默认**锁止、不可调整**，这边开了也不会顺手把它放开，那边也拖不动这边。
>
> 涩涩的时间参数全部**独立**，不跟全局 `moodFillHours` 走，也不牵动其余六维：
> 余温下限 `lustFloorPercent` / 自涨封顶 `lustSelfCapPercent` / 回落耗时 `lustDecayHours` /
> 自涨基准 `lustFillHours` / 单次涨幅 `lustTeaseStepPercent`，面板上随时改。

**挑逗怎么认**：本地正则先筛 —— 强信号（明显的）直接算；弱信号（拿不准的）再问一次模型
（`temperature 0`，只让它回「是 / 否」，同一会话 20 秒内只问一次，免得连发几条烧一堆调用）。
涩涩关着的时候连正则都不跑，不花 token。

涩涩**参与打分**：涨得高会让她更容易主动开口（最多 +12 分，见 `lib/policy.mjs` 的 `lustPart`）；
主情绪是涩涩时，念头里的语气提示会变成 `flirty`。两层开关没全亮时这一项恒 0，也不参与主情绪评比。

### 存哪儿、关了会不会没

情绪不是内存里的临时数，是落盘的：

| 文件 | 内容 |
|---|---|
| `alive-state.json` | 权威状态，`mood` 字段就是这七个数 |
| `alive-mood.json` | 每次落盘顺手写的快照，带时间戳、百分比、每颗滑条的倍率和满值时间，肉眼能看 |
| `Notfirstrun.md` | **首次运行标记**。它在 = 已经跑过；删掉它 = 下次启动当第一次装：七个情绪归 0、`alive-state.json` 重写成空的 |

`alive-mood.json` 的写入频率可以调：**百分比有变化就立刻写**；同一组百分比反复重写的情况下，
最短间隔由 `moodSnapshotIntervalMin` 卡（默认 5 分钟，范围 1~1440，设置窗口「其他」组里改）。
想更省盘就调大（1440 = 一天最多写一次），想每一步都留痕就调小到 1（每跳心跳都写）。

- **第一次装的时候七个数全是 0**：想念 / 吃醋 / 暖意 / 担心 / 闲 / 涩涩 / 恼火一律从 0 起算，不继承任何东西。判断依据是 `Notfirstrun.md` 在不在 —— 没有就当首次，顺手把它建出来；想随时重置，删掉它就行
  （唯一例外：`alive-state.json` 被删、但 `alive-mood.json` 还在 —— 那时才会按快照把上次的情绪捡回来）。
- **每轮心跳演化完就落一次盘**（500ms 节流），不是只等关闭。
- 插件卸载 / DSH 正常退出时会再强制落一次，日志里能看到 `插件已卸载，状态和情绪已落盘`。
- 下次启动读 `alive-state.json`，按"上次心跳到现在"补算（一次最多补 6 小时，免得睡一晚醒来直接顶满）。
- 万一 `alive-state.json` 被删了或读坏了，启动时会用 `alive-mood.json` 把上次的情绪捡回来，日志里写 `状态文件不在，用情绪快照（…）恢复了上次的数值`。

## 情绪怎么影响她

情绪不只是用来算「要不要开口」的分数，它会真的影响她说话。四件事：

### 1. 写进系统提示词（`moodInjection`，默认开）

主情绪 ≥ 25% 时，每轮往提示词里注入一两行 —— 她自己知道现在什么心情：

```
【你现在的心情】想他 72%（活人感插件自动给的，不必复述数字）
→ 黏人、想贴着他，说话带点撒娇和「你都不理我」。
```

情绪很淡（< 25%）时不注入，等于没有这一段，省 token 也不出戏。

### 2. 突破额度主动开口

| 参数 | 默认 | 作用 |
|---|---|---|
| `emotionBypassQuota` | 开 | 情绪上来了，每小时 / 每天配额用完了也照发 |
| `emotionBypassMaster` | **关** | 连总开关（`enabled`）关着也发 —— 危险选项 |

**这两个开关都绕不过这些闸门**：深夜（`deepNightHours`）、静音、
你说过「别发了」（当天封顶）、你刚说过话的静默期。
那些是「别打扰他」的底线，不是额度问题，所以永远守。

### 3. 先甩一张表情（`memeChancePercent`，默认 40）

主动开口时按这个概率先发一张表情包。掷中之后随机二选一：

- 一半：**先发表情，隔一会儿再说那句话**
- 一半：**只发这张表情，这次不说话**

表情走的是 qq-bot 的 `qqMeme` service，闸门和记账跟模型自己调 `send_meme` 完全一致
（最小间隔 `memeMinIntervalMin` / 每小时上限 `memeMaxPerHour` / 概率 `memeProbability`），
所以不会出现「alive 把配额吃光、模型自己再也发不出来」。

表情关键词按主情绪挑：想他→喜欢，吃醋→生气，暖意→比心，担心→难过，
闲→日常，恼火→拒绝，涩涩→好色，平静→日常。

### 4. 没有悬着的事也能开口（自发开口，`freeTalkEnabled` 默认开）

**这是 0.3.0 补的缺口。** 在那之前，整条投递链只认「悬着的念头」（open loop），
而念头只有一个来源：你说的话里带离开意思（「我去洗澡」「等我一下」「我先睡了」）。

于是就有一个死角：你说一句「好」结束对话 → 所有念头被关成 answered → 她一整晚一声不吭，
**想他 100% 也没用**，因为心跳第一行就是「没有到点的念头就 return」。

现在补了一条不靠事件、靠情绪攒的路：没有念头时，她自己造一条。

三个门槛缺一不进：

| 参数 | 默认 | 门槛 |
|---|---|---|
| `freeTalkSilenceMin` | 15 | 你在 QQ 里安静满这么久（刚聊完不插嘴） |
| `freeTalkGapMin` | 45 | 距上次自发够久（自发比"他说要走"轻，别太密） |
| `freeTalkMoodPercent` | 45 | 最主导的那一维情绪到线（想他 / 闲 / 担心 / 吃醋 / 涩涩） |

造出来的念头**不跳闸门**：静音、深夜、「别发了」、配额、冷却、你正在跑 turn ——
一条都绕不过去，走的是跟别的念头完全一样的 `checkGate` + 打分。

想关掉就取消勾选「启用自发开口」，退回「只在你走了之后才追」的老行为。

> 顺带一个诊断：设置窗口「现在为什么不会发」会把自发卡在哪一条写出来
> （安静得不够 / 隔得太近 / 情绪没到线），不用再靠猜。

### 5. 主动不只是「开口」—— 她可以用手（2026-10-26 晚加的）

以前她的主动只有两条路：说一句话、或者发一张表情。现在 qq-bot 给了她手
（戳一戳 / 发说说 / 分享卡片），所以「主动」就扩成了「互动」。

每次投念头时，插件按当前情绪算一张**菜单**，随念头一起递给她：

| 情绪 | 会放进菜单的动作 |
|---|---|
| 想他 / 涩涩 / 吃醋 ≥ 30~35% | 戳一戳（`qq_poke`）—— 不用说任何话 |
| `memeChancePercent > 0` | 发一张表情（`send_meme`） |
| 闲 ≥ 30% 或 暖 ≥ 40%，且不是深夜 | 发条说说（`qq_qzone` 的 post） |
| 闲 ≥ 50%，且不是深夜 | 分享一个链接卡片（`qq_share`） |
| 永远都在 | 说一句话 |

由她自己从菜单里挑一件。挑「戳一戳」时她只调工具、不输出文字，
qq-bot 出站那句 `if (text === '') return` 会兜住，不会发一条空消息出去。

**菜单不是额度。** 真正的额度在 qq-bot 那一侧 —— 只有它知道她真调了什么：

| 项 | 默认 | 配置项 |
|---|---|---|
| 戳一戳 | 5 次/天 | `interactPokeMaxPerDay` |
| 发说说 | 1 条/天 | `interactQzoneMaxPerDay` |
| 分享卡片 | 1 次/天 | `interactLinkMaxPerDay` |

这三样**不走说话的额度**，跟 `maxPerDay` 完全分开算。理由：戳一戳不是聊天，
发说说更是替你在社交圈公开发言，混在一个池子里会互相挤占。

> ⚠ **说说默认所有人可见**（`interactQzoneUgcRight: 1`）。所以念头里带了一条硬规则：
> 不许出现「他」「我对象」「男朋友」这类关系词，不许出现学校 / 课程 / 住址 / 行程，
> 只能写抽象心情、风景、吃的、日常感想。写不出来就别发，改成戳一下或者直接说话。

### 6. 说完晚安就别再找了（道别闭环，2026-10-27 加）

场景：她说「晚安，早点睡」→ 他回「晚安」→ 以前的系统把这条当成**一轮新对话**，
于是她又回一句「晚安呀」→ 他没完没了。

道别是句号，不是逗号。现在两边各管一段：

| 在哪 | 管什么 |
|---|---|
| qq-bot | 她已说过道别 + 他这句也是道别 → **这条直接吞掉，不回** |
| dsh-alive | 她最后一句是道别、之后他没再说话 → **这轮不主动**（默认 10 小时） |

`goodnightSilenceMin` 就是这个「不再找你」的时长。10 小时的意思是：
一句话把整晚封住，天亮他说话了自然恢复。

**不会误伤的情况**：他要是接着说事（「对了明天那个记得带」），照常回；
隔了 3 小时以上，算新的一轮，也不再拦。


## 她什么时候不说话（12 道闸门，任一不过就放弃）

关着 / 强关 / 静音期 / 你正在跑 turn / 你刚说完话 12 分钟内 / 冷却中 /
小时或日配额满 / 打扰欠账 ≥ 45 / 这条已经追够次数 / 在禁言时段 / 你最后一句是"别吵"。

**闸门不过不补偿、不补发** —— 错过就错过，不会攒一波突袭。


觉得太吵：`maxPerDay` 降到 1、`threshold` 提到 70、`cooldownMin` 提到 120。
觉得太木：`threshold` 降到 45、`minSilenceMin` 降到 8。

## 长期运行（24 小时常开）

移植到常开的机器上之前，这里把"会不会越跑越胖"逐条说清楚 —— 结论：**没有会无限涨的东西**，插件本身不背内存泄漏的锅。

### 内存

所有会攒的数组都有硬上限，且是**裁剪式**（不是只停止 push）：

| 东西 | 上限 | 在哪儿裁 |
|---|---|---|
| `loops`（挂着的念头） | 40 条 | `addLoop` 里 `slice(-40)` |
| `focus.shortTerm`（短时记忆） | 24 条 × 400 字 | 每次 push 后 `splice` |
| `episodes`（投递记录） | 200 条 | 每次落盘前 `slice(-200)` |
| `rhythm.hourly` | 固定 24 格 | 不增长 |
| `stats.byKind` | 按 loop 类型聚合，类型是有限枚举 | 不增长 |

实测：连续灌 400 件不同的事进去，`loops` 稳定在 40，`alive-state.json` 约 25 KB，堆内存 300 轮 `status()` + 日志后从 6 MB 涨到 7 MB（正常 GC 抖动，不随轮数线性涨）。

### 日志

- **2 MB 轮转**：`alive.log` 涨到 2 MB，下一次写入前把它滚成 `alive.log.1`，更老的直接丢。常开一年最多占 4 MB。
- **心跳不再刷日志**：以前"拿不到目标会话"是每跳一条（24 小时 = 1440 行/天），现在十分钟一条。唤醒失败那条本来就是十分钟去重。
- **读日志只读尾部 32 KB**：`/api/dsh-alive/state` 返回的 `logTail` 是从文件末尾读的，不会把几 MB 整份字符串塞进内存。

### 定时器和监听

- 一个 `setInterval`（心跳）+ 一个 `setTimeout`（保存节流）+ 两个 `watchFile`（配置、控制信箱），全部在插件卸载时清掉/`unwatch`。
- 卸载时强制落一次盘（状态 + 情绪快照），日志里会写 `插件已卸载，状态和情绪已落盘`。
- 同一份 `dataDir` 上如果还挂着一份活实例（上次卸载没跑完 → 双心跳、双倍投递），启动时会记一条 WARN 提醒重启 DSH。

### 磁盘写入量

| 文件 | 频率 | 估算 |
|---|---|---|
| `alive-state.json` | 每轮心跳一次（60s），约 13~25 KB | 20~35 MB/天 |
| `alive-mood.json` | 百分比有变化，或距上次 `moodSnapshotIntervalMin` 分钟（默认 5，面板可改） | 几十 KB/天 |
| `alive.log` | 只在有事件时写 | 平时几 KB/天 |

一年下来 7~13 GB 的写入量，普通 SSD / SD 卡都无压力。嫌多可以把 `tickMs` 调大（60 秒 → 5 分钟），写盘频率跟着降 —— 但心跳变粗，"她"的反应也会跟着钝，自己权衡。

### 真正要盯的

插件只是个 Node 模块，内存大头在宿主（DSH / Electron）和 agent 的会话历史上，不在它这儿。常开机器上更值得看的是：

- DSH 进程的 RSS 是否随天数缓慢上涨（那是宿主的事）
- `alive.log` 里有没有反复出现的 ERROR（真出循环报错时，先看它）

## 已知边界

- **DSH 关掉就不说话**（插件在宿主进程里）。
- QQ 会话必须先存在（你在 QQ 里说过一句话），否则拿不到 agent。
- 抽取是本地关键词 + 启发式，**不调模型** —— 宁可漏判，不要误判。
- `emotional` 型（你难受时陪着）还没做，容易越界，后置。
